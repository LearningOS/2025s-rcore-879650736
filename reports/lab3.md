
## 1.stride
### **分步解答**

---

#### **1. 问题 1：实际情况是否轮到 p1 执行？**
**答案**：**不会**，实际由 p2 执行。  
**原因**：  
- p2 执行后，其 stride 更新为 `250 + 10 = 260`，溢出后为 `4`（8 位无符号）。  
- 比较 `p1.stride = 255` 和 `p2.stride = 4` 时，`4 < 255`，p2 会被选中。  
**关键点**：  
  无符号数比较时，溢出后的值会被视为更小，导致调度错误。

---

#### **2. 问题 2：为何 STRIDE_MAX – STRIDE_MIN <= BigStride / 2？**
**核心逻辑**：  
- 当所有进程优先级 `≥ 2` 时，步长 `step = BigStride / priority ≤ BigStride / 2`。  
- 进程每次调度后，其 stride 增量最大为 `BigStride / 2`，因此系统中任意两个进程的 stride 差值不会超过 `BigStride / 2`。
即`STRIDE_MAX – STRIDE_MIN <= BigStride / 2。`  
**示例**：  
  若进程 A 的 stride 为 `S`，进程 B 的 stride 为 `S + BigStride/2`，则 B 执行后步长最多增加到 `S + BigStride`（溢出为 `S`），差值仍不超过 `BigStride/2`。

---

#### **3. 问题 3：比较器实现（补全代码）**
```Rust
impl PartialOrd for Stride {
    fn partial_cmp(&self, other: &Self) -> Option<Ordering> {
        const BIG_STRIDE: u64 = 255; // 8-bit 场景
        let a = self.0;
        let b = other.0;
        let diff = a.wrapping_sub(b);
        
        // 判断是否溢出（差值超过半数）
        if diff > BIG_STRIDE / 2 {
            // a 实际比 b 大（环形意义下更小）
            Some(Ordering::Greater)
        } else {
            Some(a.cmp(&b))
        }
    }
}
```
